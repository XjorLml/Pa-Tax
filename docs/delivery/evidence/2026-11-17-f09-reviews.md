**First-run failures, all in the tests:**
- An existing directory test used `sort=rating` as an "unknown" value; it now uses `sort=price`.
- One assertion expected `&amp;` in a link; Blazor writes `&` in attributes.
- One expected the `#review-…` fragment in the redirect's address, which isn't sent.
- One looked for the client's full name across the whole page, where the header shows the signed-in user's own name. It now looks only in the Reviews section.
- A forged review post expected 403. Blazor answers 400 when the page drew no form of that name; the same holds for the forged reply.

**What the tests cover:**
- **Rule tests:**
  - **Names:** the short name, including one-word and empty names.
  - **Average:** to one decimal, and none with no reviews.
  - **Validation:** stars must be whole numbers from 1 to 5; text is optional and up to 1,000 characters.
  - **Domain:** the limits on stars, text and replies.
  - **Eligibility:** no chat; only the client wrote; the accountant replied; a visitor; an accountant; an unlisted profile.
  - **One review per pair:** a second post updates it, and the listing follows the last change.
  - **Deleting** a review.
  - **Listing:** newest first, with short names only.
  - **Replies:** only the owner replies, the reply is editable, and empty or long replies are refused. A reply stays when the review changes.
  - **Failures:** saves report "failed" when the database is unreachable.
- **Data test:** "Highest rated" by average, then count, then name, with unreviewed accountants last across two pages.
- **Web tests:**
  - the visitor's states;
  - the reason for a client without a reply, and a forged review post (400, nothing stored);
  - posting, updating and deleting with redirects;
  - the card's rating line;
  - an invalid post keeps the text (422);
  - replying and editing, with an empty reply refused and a client's forged reply refused (400);
  - an unknown accountant's review page (404);
  - the sort links and the hidden `sort` field.
